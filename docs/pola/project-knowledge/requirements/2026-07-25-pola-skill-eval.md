# pola-skill-eval 需求

## 原始需求

在 `PolaSkills/pola-skill-eval/` 创建一个用于评测其他 Agent 生成 Skill 的 Skill，并在完成测试后仅将该子目录提交到 `PolarisW007/PolaSkills`。评测重点是：

1. Skill 是否可用，能否比无 Skill 基线更好地完成目标任务。
2. Skill 是否健壮，能否处理无效输入、超时、失败、边界条件和不安全行为。
3. Skill 的执行效率和性能是否可接受，包括耗时、上下文体积、输出体积、工具调用和成本信号。
4. 交付一个可重复运行的 harness，而不是只靠主观阅读给分。

## 目标

- 提供一个薄编排 Skill，把评测流程规范化为“静态检查 → 评测套件校验 → 配对执行 → 确定性评分 → 性能统计 → 发布结论”。
- 支持 `baseline`、`candidate` 和可选 `old` 三个评测臂，在隔离工作目录内执行同一批任务。
- 同时输出机器可读 JSON 和便于人工审阅的 Markdown 报告。
- 将硬门禁、证据、统计置信度和软评分分离，避免用一个不透明总分掩盖致命问题。
- 默认离线、标准库、自包含；真实 Agent 运行器通过显式 argv 适配器接入。

## 用户与使用场景

- Skill 作者：在发布前自测生成的 Skill。
- Skill 审阅者：复核 Skill 是否真正改善任务完成率。
- Agent 平台维护者：对同一 Skill 的不同版本做回归和性能比较。
- CI/发布门禁：用稳定退出码阻止结构错误、安全高危或关键用例失败的 Skill 发布。

## 范围

### 包含

- `SKILL.md` 元数据、结构、引用、脚本语法、体积和风险模式的静态检查。
- 可复用的 JSON 评测套件格式与严格校验。
- 不使用 shell 的命令行运行器适配，支持占位符注入。
- 新鲜工作区、超时、输出上限、环境变量白名单和并发上限。
- 触发正例、触发反例、核心任务、健壮性、安全与性能用例。
- 确定性 grader：退出码、文本、正则、响应内容、文件、JSON 路径、耗时、输出体积和 Skill 是否被调用。
- 成功率、相对基线提升、触发 precision/recall/F1、p50/p95、输出字节，以及 runner trace 提供时的 token、成本和工具调用统计。
- `quick`、`standard`、`release` 三种评测深度。
- Skill 自身的离线单元测试和端到端 harness。

### 不包含

- 内置某一家模型厂商的付费 API 客户端。
- 替代领域专家判断语义质量。
- 自动修改、自动安装或自动发布被评测 Skill。
- 自动执行生产任务、发送消息、访问真实用户数据或使用隐式凭证。
- 以单一总分作为发布依据。

## 风险等级

**P2。** 动态 harness 会执行调用方提供的本地命令，并可能评测由 Agent 生成的未知脚本。风险包括无限执行、超大输出、路径逃逸、secret 继承和结果伪阳性。

## 稳定性与安全约束

- 动态执行必须显式传入 `--execute`；默认只生成执行计划。
- 命令必须是 argv 数组，禁止 `shell=True`。
- 单次运行超时范围为 1–600 秒，默认 60 秒。
- 单次 stdout/stderr/响应累计上限为 10 MiB，超过上限终止并记录证据。
- 并发范围为 1–8，默认 1。
- 每个 case/arm/trial 使用独立临时工作区。
- grader 的相对路径必须位于当前运行工作区内，拒绝 `..` 和绝对路径。
- 默认只继承最小环境变量白名单，不继承 token、cookie、key、secret 等变量。
- 不跟随指向 Skill 根目录之外的符号链接读取内容。
- 报告不得记录凭证；输出目录必须由调用方指定，不能写入被评测 Skill 安装目录。
- harness 默认离线；是否允许网络由外部 runner 自己显式控制和记录。

## 评测模型

### 硬门禁

以下任一条件命中时不能以软分数覆盖：

- 缺少或无法解析 `SKILL.md`。
- frontmatter 缺少 `name` 或 `description`，名称非法或与目录不一致。
- 本地引用越界或缺失。
- 发现 critical 安全风险。
- 评测套件或 runner 配置无效。
- 关键 grader 失败、执行超时或证据不足。
- release 模式没有触发正反例、核心任务、健壮性和性能覆盖。

### 核心维度

1. **可用性**：任务成功、指令清晰、引用可达、相对无 Skill 基线有正向提升。
2. **健壮性**：边界输入、错误恢复、超时、输出上限、路径隔离、重复执行。
3. **效率与性能**：静态上下文体积、运行耗时 p50/p95、输出体积、token/成本/工具调用信号。
4. **触发与共存**：该触发时触发、不该触发时不抢占，并能与相邻 Skill 共存。
5. **可维护性与泛化**：结构清晰、确定性逻辑脚本化、不过拟合少量提示词、证据可复现。

### 决策状态

- `pass`：所有硬门禁通过，关键指标满足阈值，证据充分。
- `conditional`：没有致命问题，但存在需要人工确认的高风险发现或统计证据不足。
- `inconclusive`：runner、样本量或 trace 不足，不能形成可靠比较。
- `blocked`：环境或配置阻止评测完成。
- `reject`：结构、安全或关键功能门禁失败。

## 验收标准

1. **A1**：`pola-skill-eval/` 符合 Agent Skill 目录规范，包含 `SKILL.md` 和 `agents/openai.yaml`。
2. **A2**：`SKILL.md` frontmatter 只包含 `name`、`description`，正文少于 500 行。
3. **A3**：静态检查器能区分合格 fixture 和至少包含元数据、引用、语法或安全问题的不合格 fixture。
4. **A4**：评测套件校验器能拒绝重复 ID、非法阈值、未知 grader、路径逃逸和 release 覆盖不足。
5. **A5**：配对 harness 能对 baseline/candidate/可选 old 运行相同 case，每次使用新工作区。
6. **A6**：超时、输出上限、失败退出码和 runner 无效输出都有明确状态与证据。
7. **A7**：报告同时包含 JSON、Markdown、硬门禁、逐 case 证据、相对提升和 p50/p95。
8. **A8**：性能 harness 对静态检查和端到端评测设置宽松但明确的回归预算。
9. **A9**：运行 Codex `quick_validate.py`、Python 编译、单元测试和端到端 harness 全部通过。
10. **A10**：运行 `git diff --check` 和 secret 关键词检查，不提交真实凭证或运行缓存。
11. **A11**：GitHub 变更只包含 `pola-skill-eval/` 子目录及其匹配的 Pola 工程记录，不夹带本地现有脏改动或其它项目历史。
12. **A12**：本地需求、PRD、SDD、测试报告和开发日志与实际实现一致。

## 不影响功能使用的验证路径

本次新增独立 Skill，不修改已有 Skill 的入口、脚本、数据、登录态、上传下载或历史记录。需要验证：

- 现有目录均未被覆盖或移动。
- 新 Skill 可从自己的目录独立运行。
- 测试输出只写入临时目录。
- 离线 harness 不访问公网、不要求凭证。
- 本次没有用户可见 Web 页面，因此 Browser 截图不适用。

## 发布与回滚

- 发布：基于 `PolarisW007/PolaSkills` 最新 `main` 创建独立分支，在干净临时仓库中只添加 `pola-skill-eval/` 及其匹配工程记录，完成检查后发起 PR。
- 回滚：对该独立提交执行 Git revert，或删除目标子目录后提交；不会影响本地其它 Skill。
