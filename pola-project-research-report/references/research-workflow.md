## 1. 范围识别

先把“目录里的所有项目”转成可核对清单。不要直接按文件夹数量计数。

一个研究对象可以是：

- 可运行软件、服务、CLI 或桌面应用。
- Agent Skill、规则包、模板或工作流。
- 教材、论文库、数据集或内容镜像。
- 多个项目的技术对比或选型专题。
- 内部研究、评测或交付流水线。

以下内容默认不单独计为研究对象：

- `node_modules`、`vendor`、构建输出、缓存、虚拟环境。
- 第三方源码中的普通 README、贡献指南和许可证。
- 同一项目的 raw、output、article 三层研究产物。
- 交付索引、测试报告和开发日志。

同一对象有选型报告和机制专项时，计为一个研究对象、两份主报告，并在总目录同一行展示。

## 2. 项目类型判断

先判断项目形态，再决定研究重点：

| 类型 | 重点证据 | 特别边界 |
| --- | --- | --- |
| 运行型产品 | 入口、模块、数据、权限、部署、测试 | 性能、可靠性、运维、数据安全 |
| SDK/库 | API、核心抽象、扩展点、兼容性 | 版本、线程安全、错误语义 |
| Agent Skill | 触发描述、指令、references、scripts、宿主依赖 | Skill 不是运行时，效果需真实任务验证 |
| 教材/资料库 | 内容组织、覆盖度、更新机制、消费方式 | 不冒充可运行软件或生产实现 |
| 数据/内容镜像 | 来源、格式、更新、版权、完整性 | 内容权利和代码许可证分开 |
| 专题对比 | 比较口径、样本、版本、可重复性 | 不把不同层级产品强行排名 |
| 内部流水线 | 输入、阶段产物、门禁、失败恢复 | 保留原始证据和可追溯性 |

## 3. 证据采集顺序

按成本从低到高：

1. 目录、文件清单、固定版本和许可证。
2. README、官方架构文档、配置和清单文件。
3. 入口、核心模块、数据模型、错误处理。
4. 测试、CI、构建、部署和发布脚本。
5. 本地静态分析和安全、链接、语法检查。
6. 不产生真实副作用的本地运行。
7. 官方在线文档、Release、Issue 和动态指标。
8. 需要账号、付费或外部写入的验证，仅在获得相应授权后执行。

结论冲突时，以固定源码和可重复运行证据为主，并把冲突写进报告。

## 4. 单项目研究

### 4.1 固定研究快照

记录仓库、分支、tag/commit、研究日期、许可证和范围。动态网页必须记录访问日期。

### 4.2 画出执行链

至少回答：

```text
用户/外部输入
  -> 入口与参数/权限校验
  -> 核心模块
  -> 数据、状态或第三方
  -> 输出与用户反馈
  -> 失败、恢复和后续动作
```

### 4.3 把功能绑定证据

功能表中的每项要能指向模块、配置、测试、官方文档或本地验证。README 声称但源码未找到的能力标为待确认。

### 4.4 做条件化评价

评价不是“好/坏”二选一，而是：

- 对什么用户、规模和约束成立。
- 需要付出什么部署、许可、迁移和维护成本。
- 采用前必须补哪项验证。
- 哪些场景应选择替代方案。

## 5. 批量研究

### 5.1 冻结清单

保存以下字段：

| 字段 | 含义 |
| --- | --- |
| object_id | 研究对象稳定标识 |
| object_name | 对外名称 |
| evidence_root | 源码或证据根目录 |
| report_paths | 主报告和专项报告 |
| object_type | 项目形态 |
| inclusion_reason | 纳入理由 |
| exclusions | 相关但不纳入的内容 |

### 5.2 统一合同，不统一结论

所有报告回答同一组问题，但不要强迫教材、Skill 和 SaaS 共享同一种“部署成熟度”。不适用的章节要说明原因和实际消费方式。

### 5.3 跨类型抽查

至少抽查：

- 一个运行型产品。
- 一个 Skill 或规则资产。
- 一个资料库或内容型项目。
- 一个专题对比或内部工具链。

检查结构存在不等于内容可信；抽查必须回看至少三条关键结论的原始证据。

## 6. 报告升级

升级已有报告时：

1. 先识别原报告最有价值的源码、统计、运行和风险段落。
2. 在顶部补齐决策导览，或按新合同重排。
3. 保留证据深度，删除重复、占位和空泛描述。
4. 修正失效链接、个人路径和动态信息日期。
5. 不移动报告路径，除非用户明确要求迁移。
6. 让简报、证据索引和主报告角色清楚，避免多个“主入口”。

## 7. 停止条件

遇到以下情况，不要假装完成：

- 无法判断哪些文件夹算独立项目。
- 主报告对应关系冲突且会改变统计口径。
- 关键源码、许可证或官方资料缺失。
- 需要运行付费服务、真实账号或生产写操作才能验证。
- 报告结论依赖动态事实，但无法联网核验。

可以继续完成不受影响的项目，并把阻塞项单独列出。
